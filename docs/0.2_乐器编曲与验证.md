# 0.2 — 可编辑乐器编曲

本阶段补齐原先“歌声可编辑、伴奏只能导入”的缺口。工程、歌声和音频原有文件保留；新增字段对旧工程使用兼容默认值。

## 已实现

- RustySynth 1.3.8 本地采样器，固定校验 GeneralUser GS 2.0.3 的官方源码版本与采样库摘要。
- 实际读取的 287 个预置，包含 128 个 GM 主音色、变体和鼓组；不凭名称假定已安装。
- 乐器轨允许不同音高同时发声。歌声轨继续保持单声部；同键重叠重击需要独立乐器轨。
- MIDI CC 1、7、10、11、64、91、93；界面提供力度、踏板、表情和调制通道。
- MIDI 导入导出保留音色程序、复音、鼓组与已支持控制器；原生工程包保留完整工程状态与导出尾音设置。
- 人和 Agent 使用相同的选区与原子编辑；复音轨的局部移调不改动其他音轨。
- 内置采样乐器与 VOICEVOX 歌声、WAV 伴奏共同混音，生成对齐分轨。只有实际包含歌声的渲染才请求歌声合成。

音轨界面保持平面布局，通过“类型”“音色”与表达通道切换，不增加卡套。鼓组在键盘区显示打击乐名称，低音音色使用适合的可视音区。

## 数据与边界

`Track.instrument = {bank, program, drums}`。所有编号以实际目录返回值为准，program 从 0 开始。`controllers = [{beat, controller, value}]` 按时间排序；同时刻同控制器不重复。

新增 `Project.tail_seconds`，旧工程缺省 0.35 秒，新工程缺省 2 秒，可配置 0.1–12 秒。所有分轨使用相同导出时长及主输出衰减。

本版本的逐音音高曲线和逐音颤音仍属于歌声功能，不把它们静默忽略或错误地施加给整个复音乐器轨。乐器使用已支持的 MIDI 控制器。采样合成不标为真人演奏。

MIDI 1.0 的独立通道有限；超出可表达范围或中途切换不支持的 bank/program 时明确报错，完整保存使用原生工程包。多速度/拍号、实时录音和第三方插件宿主仍未实现。

## 修复大音频阻塞控制接口

旧版在主接入循环传输完整音频。0.2 把 GET/HEAD 处理移出该循环，音频从文件流式发送，并支持单段与后缀字节范围、Content-Length 和非法范围 416 响应。

实测同时保持三条 46.9 MB 音频的慢速读取，工程读取与健康检查仍响应；该次检查的最慢往返约 46 ms。这是本机这组夹具的结果，不外推为所有设备的性能保证。

启动检查增加明确超时：已有服务监听但不响应时不擅自再开同端口实例。本阶段同时实现任务进度、安全取消、页面重连及重启恢复；后续继续长工程压力测试与更完整的运行监控。

## 任务控制实测

新增 `render_jobs`、`render_cancel`，共 26 个 MCP 工具。任务回执保留工程身份、版本、阶段、音轨、进度与终态。取消和提交边界有顺序保护；退出后仍能查询 complete / cancelled / failed / interrupted。

`jobs_report.json` 验证采样取消约 63 ms、范围外工程和实时修改不受影响、失败不公开半成品、下一次渲染可继续。`voice_cancel_report.json` 使用真实 VOICEVOX 合成，请求取消后保持忙状态，约 3.0 秒后确认停止，共享引擎仍健康。`ui_jobs_report.json` 验证真实阶段、刷新找回任务、等待取消回执、退场动效和后续歌声播放。

`restart_report.json` 使用明确标注的独立测试工程，核对本软件服务器的实际 EXE 路径后终止该进程，再重新启动：未提交任务为 interrupted，已有完成/取消/失败回执恢复，不自动重试，也不修改工程。原有 DAW 和歌声引擎未被终止。
